#+TITLE: Walkthrough Archive Guide
#+DATE: 2026-08-21

Single source of truth for archiving a fully-settled walkthrough package —
folding it into the same [[file:08-context-guide.org][CONTEXT]] directory
that already holds the research behind it, once there's nothing left to
actively reconcile. Referenced by
[[file:02-expansion-guide.org][02-expansion-guide.org]] instead of
restating it, same principle as
[[file:00-conventions.org][00-conventions.org]].

* Purpose

A walkthrough package starts as a working directory — =walkthrough.org=
plus whatever session exports and detail files accumulate while it's
actively being reconciled. Once it's genuinely done, that scaffolding has
served its purpose: keeping it around forever just makes the active
working set (the top level of =.agents/walkthroughs/=) harder to scan as
completed packages pile up.

Archiving folds a settled package into
=.agents/walkthroughs/CONTEXT/<uuid>/outcome.org= — the same
per-issue-UUID directory that already holds the research staged for it
(see [[file:08-context-guide.org][08-context-guide.org]]). Research and
outcome end up living in one place per issue, instead of a walkthrough
package and its CONTEXT directory being two disjoint trees that happen to
share a UUID.

*Archiving is closure, not a storage-shape change.* Once settled, a
walkthrough is never resumed or dragged back into an active session — it
becomes read-only reference material, the same way a raw CONTEXT research
file is: cited by some later issue if it's still relevant, but never
itself worked again. If a settled decision turns out to be wrong or needs
revisiting, that becomes a *new* issue, never a reopening of this one —
same permanence as a =DONE= node's =:BLOCKED_BY:= in
[[file:01-index-guide.org][01-index-guide.org]]. Because of that, =* For
AI Assistants= and =* Search Prompts= — both written to brief an AI or
human about to *work* the file — no longer serve any purpose and are
stripped before archiving (see the Archive Workflow, below).

* When to Archive

- The =index.org= node is =DONE=, which means the walkthrough's own
  Guide checklist is fully checked (=[n/n]=); see
  [[file:02-expansion-guide.org][02-expansion-guide.org]]'s Finishing a
  Walkthrough. The validator keeps the two in agreement, so this is one
  condition rather than two. An =ACTIVE= package still being worked
  through belongs in its full
  directory form — supporting files may still be needed for ongoing
  reconciliation, and archiving mid-work would delete evidence that
  hasn't been folded into a =*Result:*= block yet.

* Archive Workflow

1. Confirm eligibility (above).

2. *CRITICAL RULE — reconcile before you delete.* Any session-export
   (=*-SESH.<ext>=) file's pedagogically relevant content — hesitations,
   wrong first guesses, raw output not already captured in a step's own
   =*Result:*= block — must already be reflected in the walkthrough's own
   checklist before that SESH file is deleted. The settled outcome is
   going to be the *only* surviving record of this package; if evidence
   exists solely in a SESH file, deleting it is data loss, not cleanup.

3. *CRITICAL RULE — step-detail files are not disposable the way SESH
   files are.* A =<step-uuid>.org= detail file (see Step-Level Expansion
   in [[file:02-expansion-guide.org][02-expansion-guide.org]]) holds
   content that was deliberately *never* duplicated inline — unlike a SESH
   export, there's no reconciled copy elsewhere to fall back on. Before
   archiving a package that has one, inline its content into the
   corresponding step (as a =*Detail (archived inline):*= block). Never
   silently delete a step-detail file.

4. *CRITICAL RULE — remove every link that points at a file you're about
   to delete.* Reconciling a SESH file's *content* (rule 2, above) is not
   the same check as finding every =[[file:<name>-SESH.<ext>...]]= reference
   to it — the External Session Workflow's own linking rule means a
   walkthrough that properly followed it *will* contain such links (the
   Notes =*Session:*= line, and possibly inline "full session" pointers
   from individual steps). Grep for the SESH filename before deleting it,
   and rewrite every hit as plain text (e.g. "worked in an external Gemini
   session, export pruned on archiving") rather than leaving a link into
   nothing. A dangling link in the settled outcome is worse than one in an
   active package directory — there's no longer a directory listing next
   to it that would make the breakage obvious.
   #+begin_src sh
   grep -rn "01-GEMINI-SESH" .agents/walkthroughs/<uuid>/walkthrough.org
   #+end_src

5. *CRITICAL RULE — strip For AI Assistants and Search Prompts before
   moving.* Both sections exist to brief someone about to work the file;
   a settled outcome is never worked again (see Purpose, above). Delete
   =* For AI Assistants= and =* Search Prompts= in their entirety from
   the walkthrough's content. Everything else stays exactly as written —
   Problem, the worked Guide checklist with its real =*Result:*= blocks,
   and Notes (including any =*Decision:*= entries, which are usually the
   most useful citable content in the whole file) — this is a section
   removal, not a rewrite of anything that survives it.

6. Create the issue's =CONTEXT/<uuid>/= subdirectory if it doesn't
   already exist — it may well already hold research staged for this same
   issue (see [[file:08-context-guide.org][08-context-guide.org]]'s
   Naming & Lifecycle) — then move and rename:
   #+begin_src sh
   mkdir -p .agents/walkthroughs/CONTEXT/<uuid>
   mv .agents/walkthroughs/<uuid>/walkthrough.org \
      .agents/walkthroughs/CONTEXT/<uuid>/outcome.org
   #+end_src
   =outcome.org= is a fixed name, not the UUID — the directory itself
   already carries that identity, same reasoning as every other filename
   in this system staying generic while the UUID lives in the path (see
   00-conventions.org's UUID Convention). It does *not* get an entry in
   that directory's own =index.org= — unlike a raw research file, it never
   goes through the =proposed=/=approved=/=mined= review pipeline; it
   graduated from the full expansion-and-work pipeline already, and its
   identity comes from its fixed filename plus the directory's UUID alone.

   *CRITICAL RULE — rebase the file's own outbound links as part of the
   move.* A =file:= link resolves relative to the directory of the file it
   sits in, and this move changes that directory from
   =.agents/walkthroughs/<uuid>/= to =.agents/walkthroughs/CONTEXT/<uuid>/=,
   one level deeper. That makes every relative link the walkthrough itself
   contains wrong. This is a different check from rule 4 (links to files
   being deleted) and step 9 (other files' links *into* this one): both of
   those are about someone else's links, and this is about the moved
   file's own. List them before moving:
   #+begin_src sh
   grep -o "\[\[file:[^]]*\]" .agents/walkthroughs/<uuid>/walkthrough.org | sort -u
   #+end_src
   Rewrite each one for the new location:
   | Link as written in the package                | Becomes in =outcome.org=                   |
   |-------------------------------------------------+--------------------------------------------|
   | =../<something>= (index, another package, ...)  | =../../<something>=                        |
   | =../CONTEXT/<same-uuid>/<file>= (own research)  | =<file>= (now in the same directory)       |
   | =../CONTEXT/<other-uuid>/<file>=                | =../<other-uuid>/<file>=                   |
   Only the path changes; the link text and surrounding prose stay exactly
   as written, the same rule step 9 applies to other outcomes. Links inside
   =* For AI Assistants= and =* Search Prompts= need no rebasing, since
   rule 5 already removed both sections. Found by archiving the GPU
   identification walkthrough: its =../index.org=, its link to a sibling
   package, and its research citations would all have dangled after the
   =mv=. Only a manual check caught them, because this guide didn't list
   the step.

7. Delete the now-superseded supporting files and the now-empty package
   directory:
   #+begin_src sh
   rm .agents/walkthroughs/<uuid>/*-SESH.*
   rmdir .agents/walkthroughs/<uuid>
   #+end_src
   (=rmdir=, not =rm -rf= — it only succeeds if the directory is actually
   empty, which doubles as confirmation nothing was missed in steps 2-5.)

8. Update the =index.org= link for this node from
   =file:<uuid>/walkthrough.org= to =file:CONTEXT/<uuid>/outcome.org= —
   the =DONE= state itself doesn't change, only the link target. Then run
   =SCRIPTS/sync-index.py=: it sees the new =outcome.org= and moves the
   whole node into =CONTEXT/closed.org=, rebasing the link to
   =file:<uuid>/outcome.org= (see
   [[file:01-index-guide.org][01-index-guide.org]]'s Closed Issues).

9. *CRITICAL RULE — check every file that links to this package's
   pre-archive path, not just settled outcomes.* Any file that cited this
   package as an active one now has a dangling link, since the package
   just moved to =CONTEXT/<uuid>/outcome.org=. That includes settled
   outcomes, other *active* walkthroughs, and other issues' descriptions
   in =index.org=, beyond the Walkthrough line step 8 already fixed. This
   is not the "never rewritten" rule being violated: updating a =file:=
   link's *path* to follow where something moved is what step 8 does for
   =index.org= itself. An already-settled file's prose, decisions, and
   =*Result:*= blocks still never change, only a stale address. Grep the
   whole tree:
   #+begin_src sh
   grep -rln "<uuid>/walkthrough.org" .agents/walkthroughs --include=*.org
   #+end_src
   The correct rewrite depends on where the *linking* file lives, because a
   =file:= link resolves from that file's own directory:
   | Linking file                               | Old link                          | New link                          |
   |--------------------------------------------+-----------------------------------+-----------------------------------|
   | =index.org= (any line)                     | =<uuid>/walkthrough.org=          | =CONTEXT/<uuid>/outcome.org=      |
   | an active =<other>/walkthrough.org=        | =../<uuid>/walkthrough.org=       | =../CONTEXT/<uuid>/outcome.org=   |
   | a settled =CONTEXT/<other>/outcome.org=    | =../../<uuid>/walkthrough.org=    | =../<uuid>/outcome.org=           |
   | =CONTEXT/closed.org= (any line)            | =../<uuid>/walkthrough.org=       | =<uuid>/outcome.org=              |
   One exception: raw CONTEXT research files are never edited (see
   [[file:08-context-guide.org][08-context-guide.org]]'s byte-for-byte
   rule), so a path they mention stays as written, as a historical
   reference. When
   archiving two packages that link to each other in the same pass, apply
   step 6's outbound rebasing and this step together, so each link is
   computed from its file's *final* location. Found by archiving the
   machine-measurement walkthrough: the original =outcome.org=-only grep
   would have missed four issue descriptions in =index.org= and one active
   walkthrough, and the table's single example was wrong for the one
   location the grep did search.

10. Run the validator.

* What the Validator Checks

- A settled outcome (=CONTEXT/<uuid>/outcome.org=) must sit in a
  subdirectory whose name is a valid UUID matching some =index.org=
  node's own =:ID:=, and that node must be =DONE= — same requirement as
  an active package directory, just checked against
  =CONTEXT/<uuid>/outcome.org= instead of =<uuid>/walkthrough.org=.
- A UUID must resolve to exactly *one* active location — either the
  active =<uuid>/= directory or =CONTEXT/<uuid>/outcome.org=, never both.
  A leftover package directory after archiving is a hard failure
  (archiving is a move, not a copy), not a warning.
- Problem, the Guide checklist, step =:ID:=s, and =*Result:*= blocks are
  checked identically to an unarchived =walkthrough.org=. Archiving
  changes where the file lives, what it's named, and *removes* two
  sections — it doesn't loosen what's required of the sections that
  remain.
- =* For AI Assistants= and =* Search Prompts= are the opposite of
  required on a settled outcome — =SCRIPTS/validate-walkthroughs.py=
  *fails* a =CONTEXT/<uuid>/outcome.org= that still has either one, the
  mechanical enforcement of CRITICAL RULE 5 above.
- Every =[[file:...]]= link in a settled outcome must resolve relative to
  =CONTEXT/<uuid>/=, the same dangling-link check an active
  =walkthrough.org= gets. This is the mechanical backstop for step 6's
  outbound-link CRITICAL RULE: an un-rebased =../index.org= fails here.
  The rule still exists so the links get fixed *during* the move, not
  discovered by the validator afterward.
- There is no supporting-files check for a settled outcome (no
  =NN-<tool>-SESH.<ext>= linking rule to enforce) — by design, nothing but
  the single =outcome.org= file survives archiving into its CONTEXT
  directory.
- A settled outcome must contain *no* =[[file:...-SESH.<ext>...]]= link at
  all — since a SESH file can never legitimately exist next to it, any
  such link is guaranteed dangling. This is the mechanical version of
  CRITICAL RULE 4 above.
- =outcome.org= itself is exempt from
  [[file:08-context-guide.org][08-context-guide.org]]'s "every CONTEXT
  file needs an =index.org= entry" check — it's the one file in a
  =CONTEXT/<uuid>/= directory that doesn't participate in the
  =:SOURCE:=/=:STATUS:= review pipeline (see Archive Workflow step 6,
  above). A =CONTEXT/<uuid>/= subdirectory whose *only* file is
  =outcome.org= doesn't need an =index.org= at all — there's nothing to
  index.

* Best Practices

1. Archive only fully-checked walkthroughs — see When to Archive above.
2. Reconcile fully before deleting anything — the two CRITICAL RULEs in
   the Archive Workflow exist because deletion here is not easily
   reversible; get it right before running =rm=.
3. *Do strip =For AI Assistants= and =Search Prompts= on archive* —
   reversed from this guide's own earlier position, which said not to.
   That earlier rule assumed a settled walkthrough might still be dragged
   back into an active session; this system's actual usage never does
   that — a correction always becomes a new issue, never a reopening of
   an old one (see Purpose, above) — so the briefing meant for an active
   worker is dead weight on something no one will ever work again.
4. Run the validator after archiving, same as any other change to this
   system.
